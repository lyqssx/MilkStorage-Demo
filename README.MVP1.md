# MVP1 母乳储存联动 Demo｜Air2 V4 母版扩展版

本版本直接复制并扩展 Air2 V4 demo，保留原有 Device、Breast Pump 子首页、Pump Control、Log Pumping Amount 等框架与视觉风格。

## 启动方式

在项目根目录运行：

    python3 -m http.server 4180 --directory '母乳储存联动专项/MVP1-基础吸存取闭环/demo-v2-air2'

访问：

    http://127.0.0.1:4180

## 信息架构

- 底部 Tab 不新增“喂养”。
- “奶库”属于 Home 首页中的“喂养”板块；首页只保留一个奶库入口，不放补充记录、吸奶器等快捷入口。
- “喂养”在本 demo 中表现为奶库外围的视觉框架，用来承载奶库入口，不额外扩展首页功能。
- Device 页、Breast Pump 子首页、Pump Control 沿用 Air2 V4 demo 风格。
- Device 卡片进入 Breast Pump 子首页；底部 Home 回到最外层 Home。

## 三种扫码触发器

右侧悬浮窗提供三个扫码分支：

- 扫新奶袋：代表第一次使用的新袋，不触发待确认。
- 扫清洗后奶袋：代表之前有完整入库/出库销账记录的袋子，不触发待确认。
- 扫已在库奶袋：代表该袋当前已有 active 入库记录，再次入库时触发旧记录待确认。

只有“扫已在库奶袋”会产生待确认库存。

## 存奶安全 Tag

奶库列表按 PRD 结论展示三层安全级别，用户可以在宏观视图一眼区分风险：

- 绿色「规范存奶」：吸奶结束后的吸奶记录卡直接扫码入库，安全级别最高。
- 橙色「补记存奶」：补充吸奶 / 奶量记录后继续扫码入库，安全级别中等。
- 红色「奶库补存」：从奶库直接发起扫码入库，不确定因素最多，安全级别最低。

## 演示路径建议

1. Home → 喂养板块 → 奶库。
2. 奶库 → 取奶扫码 → 扫已在库奶袋 → 确认取用页。
3. 取奶确认页 → 暂不使用：返回奶库，不销账。
4. 取奶确认页 → 确认用于喂养并销账：该奶袋从当前库存移除，并计入喂养消耗。
5. 奶库 → 存奶 → 扫新奶袋 → 确认入库，观察不出现待确认。
6. 奶库 → 存奶 → 扫清洗后奶袋 → 确认入库，观察不出现待确认。
7. 奶库 → 存奶 → 扫已在库奶袋 → 确认入库，观察出现待确认库存。
8. 待确认库存 → 标记“用于喂养”或“其他/丢弃”。
9. Device → Breast Pump → Pump Control → 结束吸奶 → Log Pumping Amount → 吸奶记录卡 → 存入储奶袋。

## 本轮已验证路径

- Home 喂养板块 → 奶库 → 返回 Home。
- Home 首页只保留喂养框架中的一个奶库入口。
- 奶库 → 取奶扫码 → 扫已在库奶袋 → 确认取用页。
- 确认取用页 → 暂不使用：不销账。
- 确认取用页 → 确认用于喂养并销账：从当前库存移除。
- 奶库 → 存奶 → 扫新奶袋 → 确认入库：不出现待确认。
- 奶库 → 存奶 → 扫清洗后奶袋 → 确认入库：不出现待确认。
- 奶库 → 存奶 → 扫已在库奶袋 → 确认入库：旧 active 库存进入待确认。
- 待确认库存 → 标记「用于喂养」：待确认清空。
- Home → 补充吸奶记录 → 扫码入库：展示橙色「补记存奶」tag。
- Home → Device → Breast Pump 子首页 → Pump Control。
- Pump Control → Start Pumping → Fit Check → Hold to Finish → Log Pumping Amount → Save → 吸奶记录卡 → 扫码入库：展示绿色「规范存奶」tag。
- Pump Control → List → 手动模式选择 / 程序展开 / Confirm Switch → 返回控制页。
- Pump Control 返回 Breast Pump 子首页，底部 Device/Home 导航可用。

说明：为了网页演示更稳定，原 Air2 的「Hold to Finish」长按逻辑仍保留，同时增加了点击进入 Log Pumping Amount 的兼容交互，避免演示时因为长按事件兼容性导致路径卡死。
